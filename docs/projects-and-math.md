# Проекты, общие ответы и LaTeX

## Проекты и владение

Проект - набор материалов и чатов одного аккаунта в общей PostgreSQL. Это логическая изоляция по tenant/project, а не отдельный сервер или отдельная БД. FK запрещают связывать документ/чат с чужим проектом

Миграция b7e3a12d904f создала «Мои материалы» существующим пользователям и назначила проект старым документам/чатам без смены UUID и переиндексации. Новому аккаунту default project создаётся при первом list_projects. Если все проекты удалены, чтение списка не восстанавливает удалённый default

Клиенты без project_identifier выбирают самый ранний действующий проект. Если разрешить его невозможно, возвращается project_not_found. Чат получает проект при создании; ответ всегда читает проект из сохранённого чата. Перемещения между проектами нет

Dedup одинакового файла независим между проектами. Поиск ограничен ready документами tenant/project/profile; Qdrant получает allowlist из SQL, затем SQL повторно проверяет результаты. Ранее сохранённый ответ не становится новым документом или свидетельством

## Названия и удаление

GUI не спрашивает тему чата: «Новый чат» открывает локальный черновик, отправка создаёт запись без title_text. Репозиторий при первом begin_turn нормализует пробелы вопроса и сокращает название до 76 символов. Отдельного LLM-вызова для названия нет

Явный title_text при создании или ручной PATCH отключает automatic_title. Последующие вопросы и replay название не меняют. Названия проектов/чатов после strip ограничены 1-200 символами

Удаление чата помечает его недоступным и физически удаляет messages/turns. Файлы остаются. Удаление проекта помечает проект и чаты deleted_at, удаляет переписку, ставит все живые документы deleting и отзывает leases. Очистка файлов/vectors/chunks выполняется worker

Поздняя запись ответа не восстанавливает удалённую переписку. Tombstones проектов/чатов/документов сохраняются, корзины и undo нет. Подробнее: [очередь](answer-queue.md), [руководство](user-guide.md)

## Ответы с материалами и без

Короткие фразы из фиксированного RU/EN набора после нормализации регистра/пунктуации обходят retrieval: приветствия, благодарности, прощания, вопросы о возможностях. Это не универсальный классификатор всех разговорных формулировок

Для остальных вопросов сначала выполняется адаптивный поиск. При найденном evidence модель генерирует grounded JSON; недостаточный контекст допускает дополнительный поиск и генерацию. Если свидетельств всё равно нет, выполняется отдельная ветка общих знаний без context chunks

Общий prompt описывает RAGumentation, RAGent, загрузку файлов, проекты, поиск и источники. Отсутствие excerpts в отдельном вызове не означает отсутствия поддержки файлов у сервиса

Общий ответ сохраняет `sufficient_context=false`, пустые citations и явную пометку «Ответ из знаний модели, без источников из материалов проекта»; для вопроса без кириллицы используется английская пометка. Это успешный completed ответ без подтверждения материалами, а не обязательный отказ

Выдуманные source markers в общем ответе отклоняются. Ошибки retrieval/модели остаются ошибками. Проверки labels гарантируют принадлежность ссылки контексту, а не фактическую точность всех предложений

## Markdown и формулы

Общий renderer использует react-markdown, remark-gfm, remark-math, rehype-katex. Поддерживает dollar delimiters, скобочные TeX delimiters и math fences. Нормализация не меняет inline/fenced code и исправляет известные команды, декодированные как JSON escapes, только внутри формул

Raw HTML пропускается, Markdown-картинки заменяются текстом alt, ссылки допускают только http/https. KaTeX работает с trust=false, throwOnError=false, maxExpand=1000, maxSize=20; CSS и шрифты включены в сборку. Неизвестные/повреждённые формулы не должны ломать весь диалог

Это rendering имеющегося TeX. PDF parser не распознаёт математическую вёрстку или изображения как LaTeX. Для исходной вёрстки используется [оригинал PDF](pdf-sources.md)
