# Адаптивный поиск

Поиск выбирается автоматически, без переключателей в интерфейсе. Сверено 13 октября
2026 года с [AdaptiveSearch](../src/study_rag/application/adaptive_search.py),
[генератором](../src/study_rag/adapters/generation.py),
[семантической проверкой](../src/study_rag/adapters/evidence_review.py) и
[репозиторием документов](../src/study_rag/adapters/repositories/documents.py).
Отбор использует существующие chunks и embeddings; отдельного сохранённого обзорного индекса нет.

## Планирование и границы вопроса

Перед поиском Qwen возвращает `SearchPlan`: самодостаточный вопрос, внутренний `scope_name`,
1–4 поисковых формулировки и тематические ключевые слова. План получает только предыдущие
завершённые пользовательские сообщения; старые ответы не задают фактические границы поиска.
Явный запрос на обзор всей книги/проекта дополнительно защищён от сужения прежней темой.
Для «найди ещё» восстанавливается последний широкий пользовательский вопрос.
Полное имя файла, совпавшее в вопросе без учёта регистра, ограничивает поиск этим файлом.
Это сопоставление имён, а не универсальное распознавание любых названий книг.
Запрос про книгу без указания всего проекта
использует PDF-документы, если они есть. Материалы других проектов и пользователей недоступны.

## Поиск и расширение

- Конкретный вопрос: векторный поиск, по умолчанию до 6 итоговых фрагментов.
- Сравнение: до 3 запросов по умолчанию, до 12 фрагментов с чередованием результатов разных запросов.
- Если векторных совпадений нет: дополнительный отбор по тематическим словам и разделам SQL-индекса.
- Если первый grounded answer признаёт evidence недостаточным: один дополнительный проход по разделам,
  объединение новых и исходных источников до 18 фрагментов и повторная генерация.
- Широкий вопрос/дополнения: просмотр индексированного текста, приоритет оглавления,
  тематический отбор с разнообразием глав/заголовков. Недавние источники получают меньший
  приоритет при поиске дополнений, но не исключаются целиком: рядом могут находиться новые сведения.

Просмотр SQL-индекса идёт страницами по 256 фрагментов. Лимит scan_chunk_limit применяется
к прочитанным chunks всего текущего проекта до дополнительного отбора названного файла.
Фильтры включают tenant, проект,
активный embedding profile, ready документы и живой проект; возвращаются исходные тексты
и реальные UUID. В памяти сохраняются до 3 лучших кандидатов на регион документа.
Английские слова из поисковых формулировок дополняют ключевые слова, если вопрос русский,
а документ английский. Главы PDF определяются по заголовкам/номерам страниц глав, Markdown —
по заголовкам; без структуры используются последовательные области документа.
Фрагменты, состоящие из нумерованных библиографических ссылок с годами публикаций,
исключаются из обзора: название статьи само по себе не подтверждает разбор темы в книге.

## Обзорный ответ

До 40 выбранных фрагментов обрабатываются порциями по 4. Каждый извлечённый пункт содержит
каноническое название для удаления дублей, исходное название, тип пункта, описание,
дословную цитату и source label. Проверяются принадлежность source label текущей порции,
наличие цитаты в исходном фрагменте и наличие исходного названия внутри цитаты.
После извлечения выполняется отдельная семантическая проверка, порциями до 12 пунктов.
Проверяющая модель получает исходное название и окно контекста вокруг цитаты, без
предположений первого прохода о типе и каноническом названии. Она определяет тип понятия,
релевантность вопросу и подтверждающую дословную цитату. Для каталога структур данных
допускаются структуры и их семейства; свойства, алгоритмы, программы, геометрические
фигуры, этапы обработки и неопределённые понятия исключаются. Упоминание названия само
по себе или подпись к рисунку в основном тексте не считаются достаточным подтверждением.
Оглавление может подтверждать название структуры/семейства. Цитата повторно сверяется
с настоящим источником и должна содержать исходное название.

Синонимы проверяются отдельным коротким запросом: для каждого нового пункта выбираются
до трёх наиболее похожих ранее проверенных названий из текущего ответа/порции или истории.
Похожесть только предлагает пары; объединение требует семантического решения о тождестве.
Сравнение выполняется по самим названиям, без свободного выбора идентификаторов из длинного
списка. Размер списка решений задан JSON-схемой и проверяется после ответа модели.
Аббревиатуры, переводы и варианты написания могут объединяться; связанные понятия,
семейство и конкретная реализация, B-tree и B+ tree должны оставаться отдельными пунктами.
Составное название не канонизируется к одному его участнику. Проверенные варианты
накапливаются в реестре имён текущего ответа и передаются следующим порциям.
Названия и ссылка на источник сохраняются от первого подтверждённого упоминания.
Для каталога свободные описания не публикуются, чтобы не приписывать пунктам непроверенные
свойства и не смешивать языки ответа.

Ответ собирается из проверенных пунктов, без повторного свободного пересказа всей истории.
Повторы канонических названий и подтверждённых синонимов объединяются;
«найди ещё» исключает названия, уже выделенные
в предыдущих ответах этого чата. Окончательные `[Sx]` соответствуют единому списку выбранных
фрагментов; карточки открывают те же реальные источники. Максимум 160 пунктов.

Пометка в ответе сообщает количество использованных тематических фрагментов и просмотренных
фрагментов индекса. Просмотр всех текстов для отбора **не означает** детальную LLM-обработку
каждого фрагмента и не гарантирует полный перечень всех упоминаний. Полноценного сохранённого
иерархического индекса сущностей пока нет. Классификация и распознавание синонимов всё ещё
зависят от модели: возможны пропуски и ошибочные решения. Дополнительная проверка
консервативна и не гарантирует исчерпывающего перечня. При том же общем бюджете времени
на обработку может попасть меньше фрагментов, чем без семантической проверки.

Один turn сохраняет общий timeout 240 секунд. Обзор получает оставшееся время за вычетом
15 секунд для публикации. Если после проверенных порций последующая порция не укладывается
в бюджет или повторно обрезается, публикуются только уже проверенные пункты с пометкой
об ограничении обработки. Непроверенный/обрезанный JSON не публикуется. Ошибка первой порции
остаётся понятной ошибкой, а не фиктивным успешным ответом.

## Настройки и диагностика

`STUDY_RAG_RETRIEVAL_LIMIT=6`, `STUDY_RAG_RETRIEVAL_CANDIDATES=24`,
`STUDY_RAG_MAXIMUM_SEARCH_PASSES=3` (1–4), `STUDY_RAG_OVERVIEW_CHUNK_LIMIT=40` (8–48),
`STUDY_RAG_SCAN_CHUNK_LIMIT=20000` (256–100000).
Порог cosine остаётся `minimum_similarity=0.35`; лексический отбор не выдаёт свой score за cosine.
Генератор принимает до 48 источников и grounded answer до 16000 символов вместо прежнего
жёсткого ограничения на 6 источников/4000 символов. Контекст по-прежнему ограничен tokenizer.

Логи `study_rag.application.adaptive_search` показывают тип плана, поисковые формулировки,
количество просмотренных/выбранных фрагментов и регионов. Тексты документов в логи не выводятся.
Ошибки `invalid_search_plan`, `invalid_evidence_extraction` и `invalid_evidence_review`
переводятся в интерфейсе. Некорректный результат проверки не публикуется.

Сведения об охвате сохраняются в Markdown ответа, отдельного REST DTO метрик поиска нет.
Просмотр индекса ограничен scan_chunk_limit, отбор - overview_chunk_limit, итог - бюджетом
времени и максимумом 160 пунктов. Увеличение числа источников не отменяет остальные ограничения.

Для «найди ещё» уже перечисленные названия извлекаются из жирно выделенных пунктов
недавних assistant messages. История ограничена history_message_limit, поэтому это не
полный постоянный реестр всего, когда-либо названного в длинном чате.

Дефолтные 6/12/18 фрагментов масштабируются с retrieval_limit, но не превышают 48.
maximum_search_passes ограничивает формулировки векторной ветки, а не суммарное число
LLM-вызовов в обзоре. Планирование, extraction, review и synonyms расходуют общий бюджет.

После изменения поиска задайте новый вопрос: replay completed request ID намеренно
возвращает прежний ответ. Изменение ширины поиска не меняет embedding_profile и не требует
новых embeddings; изменение parser и profile имеет другой порядок, см. [PDF](pdf-sources.md).
