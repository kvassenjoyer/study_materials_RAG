# Документы, PDF и просмотр источников

Реализация: [DocumentService](../src/study_rag/application/documents.py), [parser](../src/study_rag/adapters/document_parser.py), [tokenizer](../src/study_rag/adapters/tokenizer.py), [worker](../src/study_rag/application/ingestion.py), [Sources](../frontend/src/components/Sources.tsx), [PdfOriginal](../frontend/src/components/PdfOriginal.tsx)

## Форматы и ограничения

API определяет формат по расширению нормализованного имени: `.txt`, `.md`, `.markdown`, `.pdf`. GUI принимает только `.txt`, `.md`, `.pdf`. Исходное имя очищается от компонентов пути, ограничено 255 символами и не используется как дисковый путь

TXT/Markdown декодируются UTF-8 / UTF-8 BOM. PDF требует сигнатуру `%PDF-`, читаемый незашифрованный документ и хотя бы одну страницу с текстом. Пустые страницы пропускаются, page_count включает все страницы. OCR нет; смешанный PDF может индексировать только текстовые страницы

Defaults: 100 MiB файла, 5000 страниц, 20 млн извлечённых символов, 100 тыс chunks. Дополнительно распакованный content stream одной PDF-страницы ограничен 20 млн байт. Общий HTTP body ограничен file limit + 64 KiB для multipart

GUI имеет собственный фиксированный предел 100 MiB; увеличение серверной настройки не увеличивает его автоматически. Ограничения и ошибки описаны в [configuration.md](configuration.md) и [contracts.md](contracts.md)

## Извлечение и разбиение

PDF читается через pypdf по страницам. `extract_text(extraction_mode="layout", layout_mode_strip_rotated=False)` объединяет отдельно нарисованные слова по расположению. При пустом результате или обрабатываемой ошибке применяется обычное извлечение

Внешние отступы строк удаляются, внутренние пробелы колонок сохраняются, серии пустых строк сокращаются до одного разделителя абзацев. Это предотвращает создание Markdown code blocks из координатных отступов. Layout не обещает безошибочное восстановление таблиц, нескольких колонок, сложной типографики и формул

Parser выполняет синхронную работу в thread с сериализацией. Tokenizer сохраняет Unicode, хвост и границы PDF-страниц; chunks разных страниц не смешиваются. Default 512 content tokens / overlap 64 дополнительно ограничиваются байтовыми и formatted-input бюджетами в Ollama profile

Переносы и содержание исходного PDF не преобразуются автоматически в семантические Markdown-заголовки, таблицы или LaTeX. Текст нужен для поиска, оригинальная страница - для проверки вёрстки

## Прогресс и повтор

Worker записывает пакет из 16 embeddings, делает upsert vectors и только после успеха обновляет indexed_chunk_count. Процент вычисляет API: 0 при неизвестном числе, до 99% до ready, 100% после ready. Это прогресс публикации фрагментов, не оценка оставшегося времени

Обычный `POST /rest/study-rag/indexing-jobs/` с document_identifier повторяет failed. Чтобы применить новый parser к ready документу, передайте дополнительно `rebuild: true`. queued/indexing идемпотентны, deleting запрещён, deleted/чужой ID даёт 404

Rebuild сохраняет document UUID и оригинал, но заново создаёт chunks/vectors. На время queued/indexing документ исключён из поиска; это не атомарная замена готового индекса. Старые citation snapshots остаются, а границы chunks и их содержание могут измениться. Если ordinal перестал существовать, полный chunk даёт 404

Rebuild не меняет embedding profile документа. После смены backend/tokenizer/chunk profile нужно заново загрузить исходный файл; старый документ иначе получит embedding_profile_changed. Пример полностью исполняемого API-клиента приведён в [runbook](runbook.md#api-из-powershell)

## Окно источника

По умолчанию открыт **«Текстовый фрагмент»**, включая PDF. Для TXT/MD отдельной PDF-вкладки нет. Полный текст загружается по chunk UUID; сохранённый source_url не используется как адрес произвольного fetch

Для PDF доступен **«Оригинал PDF»**. Начальная страница берётся из citation.page_start, затем из chunk, минимум 1. После загрузки значение ограничивается известным page_count. Есть предыдущая/следующая страница, индикатор и «Открыть отдельно»

Оригинал загружается целиком авторизованным fetch уже при открытии PDF-диалога: переключение вкладок не запускает новую загрузку. Нативный viewer получает blob URL с номером страницы; Bearer не попадает в URL. При закрытии диалога запрос отменяется, URL освобождается. Просмотр оригинала не подсвечивает точные координаты chunk на странице

Если браузер не поддерживает встроенный PDF viewer, остаются открытие отдельно и текст. Если файл не загрузился, доступны понятная ошибка и повтор. При 404 chunk отображается сохранённая цитата; доступный оригинал по document UUID может работать независимо от исторического chunk

## Endpoint оригинала и удаление

`GET /rest/study-rag/documents/{document_identifier}/original/` требует Bearer и сначала проверяет владельца. Ответ 200 содержит исходные PDF-байты, Content-Type application/pdf, inline Content-Disposition с UTF-8 именем, Cache-Control private/no-store, nosniff и X-PDF-Page-Count при известном числе страниц

Чужой, deleting и deleted документ недоступен. Другой формат даёт 422 document_not_pdf. Отсутствующий сохранённый файл даёт 404 stored_file_not_found. Endpoint не требует ready, если оригинал существует; page_count до извлечения может быть неизвестен. HTTP Range и отдача отдельной отрендеренной страницы не реализованы

Удаление исключает документ из поиска сразу, затем worker очищает файл/vectors/chunks. История и excerpt цитаты сохраняются до удаления самого чата/проекта. Уже скачанный blob в открытом браузере не может быть отозван сервером
