# Мини-RAG для поиска ответов по учебным материалам

## Источники требований

- Запрос пользователя от 4 октября 2026 года в текущем чате.
- Раздел «Мини-RAG для поиска ответов по учебным материалам» в
  `/Users/simon-matveev/Desktop/resume_update.pdf`, страницы 1–2.
- Инструкции из `/Users/simon-matveev/Desktop/agents.zip`, распакованные в
  `.agents/skills/python-clean-code/` текущего репозитория.

Резюме задаёт функциональное описание и технологии проекта. Отдельный проект
speech-to-text из резюме не входит в текущий запрос.

## Обязательные возможности из резюме

1. Загрузка текстовых учебных материалов: конспектов, статей и других документов.
2. Токенизация материалов, выделение текстовых фрагментов и сохранение данных.
3. Вычисление векторных представлений фрагментов и вопроса моделью
   `google/embeddinggemma-300m`.
4. Поиск релевантных фрагментов по близости эмбеддингов в Qdrant.
5. FastAPI API: вопрос пользователя → поиск фрагментов → краткий ответ
   `Qwen3.5-4B` на основе найденного контекста со ссылками на фрагменты.
6. Сохранение истории запросов и возможность вернуться к предыдущим чатам.

Обязательные технологии: Python, Hugging Face, Qdrant, FastAPI, PostgreSQL.

Пользователь дополнительно подтвердил точные репозитории моделей:

- <https://huggingface.co/google/embeddinggemma-300m>
- <https://huggingface.co/Qwen/Qwen3.5-4B>

## Прямые ограничения пользователя

- Не взаимодействовать со Стефанией; не использовать её знания или скиллы;
  ничего не записывать в её базу знаний.
- Использовать правила Python из приложенного архива.
- Перед реализацией собрать описание и ответы пользователя и передать их
  отдельному агенту для проектирования архитектуры.
- Не писать код до создания хотя бы первичного файла архитектуры.
- Работать по принципу agent swarm: разделение планирования, исполнения и
  проверки; общие зафиксированные решения; ограниченные области ответственности.
- На текущем этапе модели скачиваются и работают локально. OpenRouter относится
  к финальной версии; сейчас не использовать его для инференса.
- Дополнительные вопросы по архитектуре согласовывать с пользователем.

## Полученные ответы пользователя

- Форматы первой версии: TXT, Markdown и PDF с текстовым слоем.
- Интерфейс первого, завершённого этапа: FastAPI API и Swagger `/docs`.
  Следующий согласованный этап добавляет браузерный GUI, сохраняя API.
- Сервис с авторизацией. Каждый пользователь имеет собственную базу материалов;
  все базы размещаются в одном месте, на текущем этапе localhost. Чаты и поиск
  должны быть изолированы между пользователями.
- Языки материалов: русский и английский.
- Объём: пара десятков книг и методичек, фотографии вариантов контрольных работ
  и конспекты лекций. Точный объём страниц не указан.
- Тестового корпуса пока нет. Пользователь готов подготовить его при необходимости.
- Контекст текущего разговора о разработке нужно учитывать. Это не подтверждение
  использования истории чатов внутри разрабатываемого сервиса; уточнение ниже
  подтверждено отдельным ответом.
- При ответе внутри RAG-сервиса учитывать историю текущего чата, включая
  уточняющие вопросы вроде «Покажи пример».
- В первой версии поддерживать только TXT, Markdown и PDF с текстовым слоем.
  Фотографии, OCR, рукописные материалы и формулы на изображениях отложены.

## Согласованный этап GUI

Пользователь запросил фронтенд с AG-UI интеграцией Pydantic AI:
<https://pydantic.dev/docs/ai/integrations/ui/ag-ui/>.
Сначала пользователь отложил его до завершения бэкенда, затем разрешил
реализацию графического интерфейса. Это ограничение относится к истории этапов;
текущий этап включает GUI и официальный AG-UI транспорт.

Реализация следует [первичной архитектуре GUI](frontend-architecture.md),
созданной до написания frontend: React + TypeScript + Vite,
`@ag-ui/client==1.0.1` и `pydantic-ai-slim[ag-ui]==2.54.0`.
FastAPI отдаёт собранный интерфейс на `/`; Swagger остаётся на `/docs`.
Вход и регистрация, материалы со статусами индексации, чаты, ответы,
история и защищённые источники доступны в браузере.

Вопрос проходит `HttpAgent → AGUIAdapter → Pydantic AI FunctionModel →
ConversationService.answer_question`. PostgreSQL остаётся источником истории;
retrieval и локальные Ollama модели выполняются существующим сценарием.
SSE отражает lifecycle и готовый ответ без обещания генерации по токенам.
Источники и постоянные ID сообщений интерфейс дочитывает через REST.
OpenRouter, OCR и изображения остаются будущими этапами.
